# 13. 上下文压缩（Auto-Compaction）子系统深度研究

> 本文是 `docs/source-code/` 系列的第 14 篇（专题深度研究），针对用户重点研究选题 1：**上下文压缩 / Auto-Compaction**，并覆盖其与 **tool_metadata carryover（工具记忆跨压缩边界）** 的联动。全部引用以当前仓库真实代码为准（`file:line` 已逐一核对）。

## 一、定位与结论速览

### 1.1 它在系统中扮演什么角色

OpenHarness 是一个**长对话智能体引擎**：每轮工具调用链会不断向 `messages` 追加 `assistant`（含 tool_use）与 `user`（含 tool_result）消息。若不干预，会话会无限膨胀直至突破模型的 context window。

`services/compact/` 包实现了一套**四级降级压缩阶梯**（借鉴 Claude Code 的 microCompact.ts / autoCompact.ts 设计），核心目标：

| 目标 | 手段 |
|---|---|
| **尽量省 token** | 优先用"不调 LLM"的确定性压缩（microcompact / context collapse / session memory），只有前几档都压不够才花钱请模型总结 |
| **不破坏会话合法性** | 切分时绝不切断 tool_use ↔ tool_result 对；重建后调用 `sanitize_conversation_messages` 状态机清洗 |
| **穿越边界保留关键状态** | `tool_metadata` carryover 机制把工具记忆、用户目标、最近读过的文件等打包成 `CompactAttachment` 塞进压缩后的消息流 |
| **可观测、可重试、可降级** | `CompactProgressEvent` 进度事件 + checkpoint 数组 + 失败自动 passthrough |

## 三、Token 估算引擎（压缩判定的基石）

### 3.1 `estimate_message_tokens` — `compact/__init__.py:116-131`

```python
def estimate_message_tokens(messages: list[ConversationMessage]) -> int:
    total = 0
    image_token_estimate = _vision_token_budget_per_image()
    for msg in messages:
        for block in msg.content:
            if isinstance(block, TextBlock):
                total += estimate_tokens(block.text)
            elif isinstance(block, ToolResultBlock):
                total += estimate_tokens(block.content)
            elif isinstance(block, ToolUseBlock):
                total += estimate_tokens(block.name)
                total += estimate_tokens(str(block.input))
            elif isinstance(block, ImageBlock):
                total += image_token_estimate
    return int(total * TOKEN_ESTIMATION_PADDING)
```

要点：
- **按 block 类型分别估算**：Text / ToolResult 按文本；ToolUse 按 `name + input`；Image 按固定预算（默认 3,072 token/图）。
- **整体 × 4/3 padding**（`TOKEN_ESTIMATION_PADDING`，`:75`）——刻意保守，宁多估不少估，避免接近窗口边界时爆炸。
- `estimate_conversation_tokens`（`:134-136`）只是别名，兼容旧调用方（`/usage` 命令用 `registry.py:531`）。

### 3.2 图像 token 预算 — `_vision_token_budget_per_image`，`:139-146`

`OPENHARNESS_IMAGE_TOKEN_ESTIMATE` 环境变量可覆盖（下限 64），默认 3,072。

### 3.3 单文本估算 `estimate_tokens` — `services/token_estimation.py`

15 行的小工具（按 `len(text)/4` 之类启发式，取整），所有上层估算都收敛到它。

### 3.4 阈值数学（重点）

`get_context_window`（`compact/__init__.py:1065-1077`）：


`get_autocompact_threshold`（`:1080-1092`）：

```python
def get_autocompact_threshold(model, *, context_window_tokens=None, auto_compact_threshold_tokens=None) -> int:
    if auto_compact_threshold_tokens is not None and auto_compact_threshold_tokens > 0:
        return int(auto_compact_threshold_tokens)   # 显式覆盖优先
```


> 示例（来源 `compact/__init__.py:1080-1112`；内容为示意）：
> 模型 `claude-3-7-sonnet`（200k 窗口）、未显式配置时：

## 四、触发路径（三种入口）

### 4.1 自动触发（每轮开头）— `query.py:712`

`run_query` 主循环（`query.py:633-884`）在**每轮调用模型之前**先跑一遍 `_stream_compaction(trigger="auto")`：

```python
# query.py:712-717

    yield event, usage
compacted_messages, was_compacted = last_compaction_result
if compacted_messages is not messages:

```

`_stream_compaction`（`query.py:659-697`）是"asyncio 队列桥接器"：

```python
# query.py:659-697（节选）
async def _stream_compaction(*, trigger: str, force: bool = False):
    progress_queue: asyncio.Queue[CompactProgressEvent] = asyncio.Queue()

    async def _progress(event: CompactProgressEvent) -> None:
        await progress_queue.put(event)

    task = asyncio.create_task(
        auto_compact_if_needed(
            messages,
            api_client=context.api_client,
            model=context.model,
            system_prompt=context.system_prompt,
            state=compact_state,
            progress_callback=_progress,
            force=force,
            trigger=trigger,
            hook_executor=context.hook_executor,
            carryover_metadata=context.tool_metadata,      # ← tool_metadata 传进压缩器
            context_window_tokens=context.context_window_tokens,
            auto_compact_threshold_tokens=context.auto_compact_threshold_tokens,
        )
    )
    while True:
        try:
            event = await asyncio.wait_for(progress_queue.get(), timeout=0.05)
            yield event, None
        except asyncio.TimeoutError:
            if task.done():
                break
            continue
    while not progress_queue.empty():
        yield progress_queue.get_nowait(), None
    last_compaction_result = await task
```

设计要点：
- **独立 task + 0.05s 轮询队列**：压缩是异步后台工作，期间主循环仍可 yield 进度事件给 UI，不会阻塞；
- **就地改写**：压缩器内部基于传入的 `messages` 列表**原地 mutate**（尤其 microcompact 直接改 `msg.content`），`compact_metadata` 等新消息则通过返回值替换，触发点用 `messages[:] = ...` 就地整体替换列表引用。

## 五、Level 1 — Microcompact（清旧工具结果）

**定位**：最便宜的一档，零 LLM 调用，纯文本替换。来源注释直指 Claude Code 的 `microCompact.ts`。

### 5.1 可压缩工具判定

`_collect_compactable_tool_ids`（`compact/__init__.py:785-806`）：

```python
def _collect_compactable_tool_ids(messages: list[ConversationMessage]) -> list[str]:
    ordered_ids: list[str] = []
    tool_names: dict[str, str] = {}
    result_content: dict[str, str] = {}
    for msg in messages:
        for block in msg.content:
            if isinstance(block, ToolUseBlock):
                ordered_ids.append(block.id)
                tool_names[block.id] = block.name
            elif isinstance(block, ToolResultBlock):
                result_content[block.tool_use_id] = block.content
    return [
        tool_id
        for tool_id in ordered_ids
        if tool_names.get(tool_id, "") in COMPACTABLE_TOOLS
        or is_microcompactable_tool_result(
            tool_names.get(tool_id, ""),
            result_content.get(tool_id, ""),
        )
    ]
```

两条并列条件（满足其一即可被清）：

1. **名称在白名单** `COMPACTABLE_TOOLS`（`compact/__init__.py:41-50`，8 个工具）：
   `read_file`、`bash`、`grep`、`glob`、`web_search`、`web_fetch`、`edit_file`、`write_file`。
2. **结果内容够大** `is_microcompactable_tool_result`（`services/tool_outputs.py:50-55`）：

```python
def is_microcompactable_tool_result(tool_name: str, content: str) -> bool:
    normalized = tool_name.strip()
    if normalized.startswith("mcp__"):
        return True                              # 任何 MCP 工具结果无条件可清
    return len(content) >= microcompact_tool_result_chars()   # 默认 ≥ 4000 chars
```

`microcompact_tool_result_chars()`（`tool_outputs.py:42-47`）读 `OPENHARNESS_MICROCOMPACT_TOOL_RESULT_CHARS`，默认 4,000，下限 256。

### 5.2 执行逻辑 — `microcompact_messages`，`:808-856`

```python
def microcompact_messages(messages, *, keep_recent: int = DEFAULT_KEEP_RECENT) -> tuple[list, int]:
    keep_recent = max(1, keep_recent)  # never clear ALL results
    all_ids = _collect_compactable_tool_ids(messages)
    if len(all_ids) <= keep_recent:
        return messages, 0
    keep_set = set(all_ids[-keep_recent:])      # 只保留最近 keep_recent 个可清结果
    clear_set = set(all_ids) - keep_set
    tokens_saved = 0
    for msg in messages:
        if msg.role != "user":
            continue
        new_content = []
        for block in msg.content:
            if (isinstance(block, ToolResultBlock)
                and block.tool_use_id in clear_set
                and block.content != TIME_BASED_MC_CLEARED_MESSAGE):
                tokens_saved += estimate_tokens(block.content)
                new_content.append(ToolResultBlock(
                    tool_use_id=block.tool_use_id,
                    content=TIME_BASED_MC_CLEARED_MESSAGE,   # "[Old tool result content cleared]"
                    is_error=block.is_error,                  # 保留错误标记
                ))
            else:
                new_content.append(block)
        msg.content = new_content
    return messages, tokens_saved
```

- **保留最近 `keep_recent`（默认 5，`DEFAULT_KEEP_RECENT`，`:71`）个**，旧的用 `TIME_BASED_MC_CLEARED_MESSAGE = "[Old tool result content cleared]"`（`:52`）整体替换；
- **保留 `is_error` 标记**——即使内容清了，错误状态不能丢（否则模型会把失败当成成功继续）；
- 已替换过的（content 就是占位符）跳过，保证幂等；
- **就地 mutate**，返回 `(messages, tokens_saved)`，返回 `0` 表示无收益。

> 示例（来源 `compact/__init__.py:808-856` + `tool_outputs.py:50-55`；内容为示意）：
> 会话中第 3 条 `bash` 命令 `ls -la` 输出了 2,000 行，其 ToolResultBlock 内容约 31k 字符。当它是可清工具结果中第 6 个（已保留最近 5 个）时，被替换为 `[Old tool result content cleared]`，`estimate_tokens` 记账 `tokens_saved`，`is_error=False` 保留。

### 5.3 与"工具输出三级处理"的关系

microcompact 清的是**已经进上下文**的结果；而在**工具执行当下**，引擎已先做了一层省 token 处理 `_offload_tool_output_if_needed`（`query.py:524-553`）：

```python
def _offload_tool_output_if_needed(*, tool_name, tool_use_id, output) -> tuple[str, Path | None]:
    inline_limit = tool_output_inline_chars()          # 默认 16_000
    if len(output) <= inline_limit:
        return output, None                             # ① 小输出：原样内联
    artifact_path = _tool_artifact_dir() / f"{...}.txt" # data_dir/tool_artifacts/
    artifact_path.write_text(output, encoding="utf-8", errors="replace")
    preview = output[:tool_output_preview_chars()]      # 默认 3_000
    inline = ("[Tool output truncated]\n"
              f"Tool: {tool_name}\nTool use id: {tool_use_id}\n"
              f"Original size: {len(output)} chars\n"
              f"Full output saved to: {artifact_path}\n"
              f"Inline preview: first {len(preview)} chars")
    return inline, artifact_path                         # ② 大输出：落盘 + 3k 预览
```

三级防线闭环：
1. **执行时**：>16k 的输出落盘到 `data_dir/tool_artifacts/`（`_tool_artifact_dir`，`query.py:513-516`），上下文只留 3k 预览；
2. **估算时**：ToolResultBlock 按 `content` 文本估算（内容已短）；
3. **压缩时**：microcompact 再把旧结果清成占位符。

## 六、Level 2 — Context Collapse（超长文本截断）

**定位**：确定性截断超大文本块，为 full compact 的"输入 prompt"瘦身——尤其防止 compact 请求本身因过大而失败（PTL，prompt too long）。

```python
        return None          # 没变小就放弃，避免白忙
    return result
```

关键策略：
- 只处理 **older 段**（近期消息保持原样）；
- **TextBlock 与 ToolResultBlock 同时**被压；
- **token 不变小则返回 `None`**（拒绝无效变换）——这是一条贯穿所有确定性档位的"不得变差"不变量。

### 10.1 不切断 tool 对 — `_split_preserving_tool_pairs`，`:483-503` + `_boundary_crosses_tool_pair`，`:471-480`

```python
def _boundary_crosses_tool_pair(previous, current) -> bool:
    if previous.role != "assistant" or current.role != "user":
        return False
    pending_tool_ids = {block.id for block in previous.content if isinstance(block, ToolUseBlock)}
    if not pending_tool_ids:
        return False
    result_ids = {block.tool_use_id for block in current.content if isinstance(block, ToolResultBlock)}
    return bool(pending_tool_ids & result_ids)

def _split_preserving_tool_pairs(messages, *, preserve_recent):
    if len(messages) <= preserve_recent:
        return [], sanitize_conversation_messages(list(messages))
    split_index = max(0, len(messages) - preserve_recent)
    while split_index > 0 and _boundary_crosses_tool_pair(messages[split_index - 1], messages[split_index]):
        split_index -= 1
    older = list(messages[:split_index])
    newer = sanitize_conversation_messages(list(messages[split_index:]))
    return older, newer
```

**不变量**：如果切分点恰好落在 `assistant(tool_use)` + `user(tool_result)` 之间，把分界点**往前挪**，让 tool_use 一起进 newer。因为 Anthropic 风格 API 会拒绝"有 tool_use 而无匹配 tool_result"的会话（`query.py:849-852` 的注释也重申了这一点）。

### 11.5 一个完整走查

> 示例（来源 `engine/query.py:395-510,998-1006` + `compact/__init__.py:566-733`；内容为示意）：
> 1. 用户问"帮我修好 `src/app.py` 的缓存 bug"，模型调用 `read_file`（path、offset=0、limit=200）→ `_record_tool_carryover` 记录 `read_file_state`（含 preview）+ verified_work"已检查文件 …" + work_log"读取文件 …"。
> 2. 会话增长到 168k token，下一轮开头触发 auto-compact；`compact_conversation` 拿到 `carryover_metadata=context.tool_metadata`（内含 `read_file_state` 等）。
> 3. older 段含若干 `read_file` 结果 → microcompact 把它们清成占位符（token 大降）。
> 4. full compact 后 `_build_compact_attachments` 把 `read_file_state` 打包成 `recent_files` 附件、把"已检查文件"打进 `recent_verified_work` 附件。
> 5. `build_post_compact_messages` 把边界标记 + 摘要 + 保留段 + 这些附件排进新上下文 → 模型在压缩后**仍然知道看过哪些文件、读到哪一行、下一步该做什么**（`task_focus.next_step`）。

## 十五、研究价值结论（针对"哪些值得研究"）

1. **四级降级是系统设计精华**：microcompact → context collapse → session memory → LLM full compact，前三级零模型成本，每级后重判阈值，最大化"免费压"的命中率——这是长对话成本控制的最佳实践模板。
2. **tool_metadata carryover 是"记忆穿越"的范本**：把工具执行产生的隐性状态（读过哪些文件、用户目标、plan mode、后台 agent）显性化为结构化附件随压缩边界保留，比裸摘要信息密度高得多。
3. **健壮性网络可迁移**：PTL 头部截断、tool 对保护切分、sanitize 状态机、"不变小则放弃"不变量、连续失败熔断、全链路 checkpoint——任何长上下文系统都值得借鉴。
4. **可扩展点明确**：新增压缩策略只需扩展 `auto_compact_if_needed` 的 trigger/phase + `CompactProgressEvent`；新增附件只需加 builder 函数并挂进 `_build_compact_attachments`；新 provider 容错只需扩展 `_is_prompt_too_long_error` 关键词表。
